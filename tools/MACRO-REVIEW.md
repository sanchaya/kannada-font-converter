# KGP macro review and adoption plan

Source: six Word macro templates (.dot) authored by KGP (Kannada Ganaka
Parishat), 2003-2009, provided by Sanchaya. Extracted rule tables live in
`tools/macro-extracts/*.json` (regenerate with `tools/extract-macros.py`).

## Architecture of the macros

Every converter is a character-at-a-time `Select Case` state machine over the
source bytes, with a handful of state flags (`Chukke` = anusvara dot pending,
`Baottu` = vattakshara pending, `Pa`/`Ha`/`Qa`/`Di`/`Geetu` = glyph-context
flags) that handle reordering. All converters target **Nudi** (Mono or Bi)
as the pivot encoding, and a shared pair of tables converts
NudiMono <-> NudiBi and NudiBi -> Unicode.

**Adoption strategy: keep the pivot.** For each new font X, port the
X -> NudiMono table to JS and chain it through our existing (well-tested)
Nudi -> Unicode engine:

    X  --ported table-->  Nudi ASCII  --existing a2u-->  Unicode

This reuses the 2076/2077-passing Nudi engine and means each new font is
one table + a few state rules, not a full converter. The macros are one-way
(X -> Nudi), so new fonts start as a2u only; u2a can be added later by
inverting the tables where unambiguous.

### How steps 1-4 were actually implemented

Rather than hand-porting each "complex" (state-flag) VBA rule individually,
`tools/resolve-complex.py` re-scans each rule's raw VBA, strips harmless
flag-assignment lines (`Chukke = 0`, `Da = 1`, ...), and resolves the
remaining `Selection.Text = Chr(...)` expression the same way the simple-rule
parser does. This recovered the output for most complex rules automatically;
rules involving genuine cursor movement (`Selection.MoveLeft`/`MoveRight`)
were left unresolved and those byte codes pass through unconverted (counts
are in the header comment above each map in `tools/pivot-maps.generated.js`,
generated by `tools/generate-pivot-maps.py`).

The resulting charCode -> Nudi-ASCII-fragment tables
(`PRAKASH2_X2NUDI`, `AKRUTI2_X2NUDI`, `SHREE2_X2NUDI`, `SURABHI_X2NUDI`) live
directly in `js/app.js`, along with generic `pivotAsciiToUnicode()` /
`pivotUnicodeToAscii()` functions that implement the pivot chain described
above. u2a (Unicode -> ASCII) is handled by inverting each map (Nudi fragment
-> source char, longest-match first) and running it after the existing
`unicodeToASCII(text, 'nudi')`. This works well for simple syllables but is
noticeably weaker for conjunct/vattakshara forms, because the Nudi engine's
own ASCII output for those forms doesn't always match the literal per-byte
fragment shapes the macros assumed - this is the main source of the
remaining round-trip failures (see `test/ISSUES.md`).

**Not done**: `server.js` (the optional Express API) still only implements
the Nudi engine and was not extended with the pivot maps, since it already
lacked Shree/Prakashak/Akruti support before this pass and is documented as
the secondary path (GitHub Pages / client-side is primary).
